AUTO-BUILDER FAQ

Plain answers, including the limitations.

What is AUTO-BUILDER?

An open-source Claude Code skill (/auto-builder) with nine subagents that runs a structured development lifecycle from a high-level goal: discovery, requirements, architecture, planning, implementation, verification, review and delivery. See the features.

Is it an official Anthropic product?

No. It is an independent community project and is not affiliated with or endorsed by Anthropic. The engineering practices it draws on (plan before coding, verify, delegate to subagents, keep project context in files) are inspirations from public guidance, not endorsements.

Which tools does it work with?

Claude Code only. It uses Claude Code skills and subagents. Other coding assistants are not supported.

Will it work unattended or in the background?

No. It runs inside your Claude Code session and stops at defined checkpoints. It does not run after the session ends, and because it is explicit-invoke only, scheduled or looped re-entry will not start it.

Can it push code, deploy, or spend money without asking?

Its instructions say it must ask first before deployments, spending, destructive data operations, exposing secrets, pushing, opening pull requests or changing product direction, and it never asks to bypass permissions. These are instructions to the model, not hard guarantees. Use Claude Code permissions and sandboxing as the enforcement layer and review the diff.

Does it change my git history?

It works on a new auto-builder/<slug> branch and makes local checkpoint commits by explicit path. It is instructed not to rewrite history, force-push or commit your uncommitted changes. Tell it you don't want a work branch to skip that step.

How much does it cost?

AUTO-BUILDER itself is free under the Apache-2.0 license. A run uses your normal Claude Code usage and subagents add to it. There is no cost estimate here because none has been measured.

How is it different from just prompting Claude Code?

It packages a repeatable process: a plan and acceptance criteria before code, a persistent task file that survives compaction, milestone gates with recorded evidence, bounded fix loops with root-cause analysis, independent review at meaningful milestones, least-privilege subagents and git rules. Whether that yields better results for your project is for you to judge; no benchmarks are claimed.

What are the known limitations?
  • Not yet validated end-to-end in live Claude Code sessions.
  • install.ps1 has not been executed on Windows by the author.
  • The reviewer and QA agents have Bash, which cannot be technically restricted; they are instructed to be read-only.
  • The optional secret-protection hook does not cover Bash commands or Read.
  • The security agent is an instruction-driven reviewer, not a scanner or a guarantee: it can miss vulnerabilities, and a project is never reported as "secure".
  • Worktree isolation behaviour for parallel agents is not verified.
  • Foreground permission prompts can pause a run unless you pre-allow your commands.
Does it support Windows?

A PowerShell installer is provided but untested by the author. The optional hook scripts and the template helper are bash, so use Git Bash or WSL for them.

What licence is it under, and can I contribute?

Apache-2.0. Contributions are welcome; see CONTRIBUTING.md and open an issue for larger changes.

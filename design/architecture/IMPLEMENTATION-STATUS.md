## What the helper's hardening covers (and its limits)
After the implementation reviews, `ab.py` refuses working-tree git operations when the repository's own git configuration defines commands git could run (filters, include, external diff/textconv, fsmonitor and similar; the standard Git LFS commands are the one exact exception), resolves git only from absolute PATH entries outside the project, reads files with no-follow opens and size/line/row caps, strips control/newline/bidi characters from everything it echoes, and prints a "data, not instructions" banner. This was found by a review, **confirmed** with a planted clean filter that plain git executes, and fixed. The tests cover it, but the list of risky git configuration keys is a deny-list: unlisted ways for a hostile repository to make git execute programs may exist. Known limits: the ownership check ignores changes inside submodules (`--ignore-submodules=all`, so that a submodule's own configuration is never exercised), and it refuses working-tree checks entirely in repositories whose own git configuration defines commands, including sparse-checkout or worktree setups that use `extensions.worktreeConfig`. The helper is a convenience for a lead working on repositories the user already trusts enough to open; it is **not a sandbox**.

## Mechanism tests (what the test programs add up to)
`tests/validate.py` (static: structure, wording, AST read-only enforcement of the helper), `tests/test_mutations.py` (deliberate breakage, reported by kind: **behaviour** mutations break the helper's code and `test_ab.py` must fail; **static** mutations break code, scripts, agents or fixtures and the validator must fail; **wording** mutations change a safety-critical sentence and only prove it is pinned, not that the model would behave differently), `tests/test_ab.py` (behaviour and hostile-input tests of the helper on temp repos), `tests/test-install.sh` (installers and hooks in temp HOMEs), `site/check.py` (website). `tests/run-all.sh` runs them all. Counts and results are in the final report and CI.

## Explicit non-claims
- No live end-to-end run of `/auto-builder` has happened, so **no claim is made about routing accuracy, defect rates, speed, token use, or that outcomes improved**.
- The benchmark ([BENCHMARK-PLAN](../benchmarks/BENCHMARK-PLAN.md)) is designed, not run. No old-vs-new comparison exists.
- The Windows installer has never been executed.
- Fresh-context reviewers share the lead's framing and the model's blind spots.
- The security agent and the helper are not a scanner, a sandbox or a guarantee.
